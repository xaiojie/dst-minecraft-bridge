# Local gameplay / camera additions (v2)

Two real processes and a single integrated MC player are supported. MC owns movement, player health/inventory and real blocks. DST owns native entities/health. All HTTP binds loopback. MC stage is `dst_mc_bridge:stage`, pairing persists in the copied save; every side effect is guarded by the current pair/epoch.

`POST /v2/exchange` retains protocol, pair, epoch, commands and damage_events. A `world_snapshot` command carries a monotonically increasing sequence, last applied block_revision (-1 requests a full snapshot), an ActorSnapshot in **MC coordinates**, optional terrain snapshot, terminal event results, and input_owner. Terrain rows encode a contiguous line of full ground cells; obstacle boxes are in MC coordinates and are split into local per-cell collision shapes. Snapshots replace the prior sampled region. Each response issues a fresh snapshot_ticket; the next sample echoes it. Its age on the MC monotonic clock must be at most 250 ms, and actor freshness starts at ticket issuance, so delayed snapshots cannot become fresh on arrival. The first unticketed exchange only obtains a ticket. Movement remains frozen until valid actors and terrain are ready. State snapshots are repeatable; only side-effect events use the durable ledger.

Response: snapshot_ticket, blocks (revision/from/full/changes), player (UUID, position in **DST coordinates**, MC health/max_health/alive), events, results, terrain_conflicts and input_owner. Missing block revisions trigger a complete snapshot. Player blocks remain MC chunk data; the index is reconciled against the actual save when opened. Persistent removed-cell tombstones also participate in reconciliation, protecting against MC chunk-save lag. Only full solid collision shapes are exported; water, fire and unsupported shapes remove an existing collider. Proxy blocks are invisible/no loot/unbreakable, only in the dedicated dimension. Integrated client/server share immutable collision shapes; remote Minecraft multiplayer is unsupported.

Native actor identity is saved by the dstmcidentity component. Actor bodies use the exposed physics radius and explicit height profiles (small .6, standard 1.8, epic 4 DST units). Static obstacle height currently uses 2 units because Lua does not expose the native collision-height geometry. These are approximation profiles, not an exact engine mesh export. Ground sampling covers radius 32. MC cell = 1 DST unit and X is reflected around the saved origins.

DamageEvent positions are source-space: MC for MC->DST, DST for DST->MC. Amount is source health units; 1 MC HP = 10 DST HP. MC native weapons/arrows/explosions hit real invisible living proxies; the recipient applies native defenses. The shadow player's effective native loss is intercepted after native absorption and forwarded to MC, whose health ratio then updates the shadow. An event ID and its immutable payload are persisted before applying a side effect; pending records after a crash are UNRESOLVED and require reconciliation. Within the current epoch, outboxes retry until terminal acknowledgement. DST outgoing hits are in memory and are dropped on restart/re-pair rather than replayed into a new session. The MC outbox is persisted. Re-pairing archives old MC outboxes instead of replaying them. This does not promise strict exactly-once under power loss.

TNT events are emitted after the real MC explosion. Per-target damage comes from explosion hits on the proxies. The separate native explosion event supplies effects and workable destruction, never a second blanket health reduction. Forced chunk ownership is reference-counted; pre-existing forced chunks are preserved. Creation session is retained so an old TNT cannot use a new origin.

F8 is arbitrated by native `/v2/input`: GET requires pair_hash/epoch; POST contains protocol/key/owner/version and uses a revision check. MC polls with a bounded response age, releases held keys and cursor on loss of control; native F8 works when DST is foreground. The Lua bridge restores the original controller and camera on disconnection (>2.5 s), and late generation callbacks are ignored.

Camera `/v2/camera/lease` always discovers the newest complete frame. An unchanged exact frame cannot renew its deadline. `/v2/camera/cycle` acknowledges a pose actually applied by DST, then returns the next lease. An optional local mailbox uses atomic `request.json`/`response.json` replacements and unique request IDs to avoid QueryServer callback latency. The game update applies a pose before sending its ACK; a pose read during that update is acknowledged on the following update. Mailbox failure falls back to HTTP. Image pixels remain in the shared mmap triple buffer; there is no image encoding through JSON. Frame/pose IDs are monotonic within an epoch; dimensions and transform are verified.

The renderer inserts MC world color and converted host depth at the profiled terrain→sprite boundary, with a terrain-target transition fallback for scenes without sprites. Native sprites use their original shader/alpha, with depth test enabled against that scene, and later native effects process the combined scene. Hand and GUI are captured together after MC hand rendering and overlaid in the foreground, matching MC first-person behavior. Only known shader fingerprints are used. A new DST build may require recalibration; live gates are separate from offscreen tests.
