# DST × Minecraft 第一人称联动设计 v1

日期：2026-10-21。状态：用户已确认本文的首版范围、原生合成路线与验收标准；实施计划已确认，进入逐项实现与审查。

## 1. 要实现的体验

两款真实游戏同时运行。玩家使用 Minecraft（MC）的第一人称、键鼠、物品栏和建造操作；饥荒联机版（DST）继续运行地面、物体、生物和原生行为。MC 的方块与 DST 的世界显示在同一个游戏画面中，双方的障碍和伤害能够相互影响。

用户已明确选择：MC 第一人称控制移动和建造，DST 提供世界与生物；使用原生画面合成路线。

首版限定为本机、单名玩家、独立联动测试存档、地面区域。先支持完整立方体方块的放置、拆除、堆叠和阻挡，以及 TNT 和生物伤害。DST 地形仍由原游戏提供，DST 原有素材仍是 2.5D 素材。生物不增加攀爬 MC 楼梯的能力；下地洞、海面、车辆、多人联网及任意第三方模组留在后续版本。

## 2. 已有基础与本次现场检查

- 旧临时原型已验证真实坐标同步、真实 MC TNT 爆炸，以及对应 DST 测试目标从 1000 到 900 的健康变化。证据在同目录的《首次真实联动证据》和《实际移动同步证据》中。
- 旧原型是 DST 推动 MC 的水平位置同步，不包含共享画面、方块建造联动或通用碰撞。本次需要反转移动控制权。
- 本次检查时 DST 进程在运行，MC 的本地联动接口未运行。历史证据不代表当前已连接。
- 本机为 Apple M4；DST 可执行文件为 x86_64，日志报告 OpenGL 2.1；MC 使用 ARM64 Java 21、Minecraft 1.21.11。
- DST 现有程序带有允许 DYLD 环境变量和关闭第三方库签名验证的权限；这支持尝试加载本地扩展，但不等于已验证挂接成功。
- 本地 Lua 源码包含 `TheSim:SetCameraPos/Dir/Up/FOV`，以及 `Physics:SetTriangleMesh` 的原游戏调用实例。尚未验证第一人称镜头、网格碰撞和渲染合成的实际效果。

## 3. 选择与取舍

采用原生画面合成。Fabric 客户端输出真实 MC 颜色、深度、镜头和 HUD；新建针对当前 Mac 版 DST 的本地扩展，在 DST 绘制流程中合成。两款游戏之间采用共享内存传递逐帧数据，本机 HTTP 传递世界状态与命令。

备选一是透明窗口叠加：容易先看到图像，但不能据此声称树木、角色与方块的前后遮挡正确。备选二是将 DST 场景重建进 MC：会转成素材与场景重建项目，偏离保留真实 DST 画面的目标。

现有公开参考的游戏端针对 Windows Direct3D；不能把其 DLL 直接装进本机 DST。可以参考共享内存、帧与镜头配对、碰撞代理和事件队列的设计。参考代码若实际复用，应单独核查许可证并保留声明。

## 4. 模块与数据流

| 模块 | 职责 | 运行位置 |
|---|---|---|
| MC 客户端适配器 | 第一人称操作、真实方块/HUD 渲染、颜色与深度读回、镜头发布 | Fabric 客户端线程/渲染线程 |
| MC 服务端适配器 | 方块保存、放置/拆除校验、碰撞代理、伤害处理 | MC 服务端线程 |
| DST Lua 模组 | 世界与生物采样、镜头与对应角色、原生碰撞体、原生伤害、存档标识 | DST 游戏线程 |
| DST 本地图形扩展 | 绘制挂接、实际矩阵与深度检查、MC 帧合成、HUD 层与状态恢复 | DST 渲染线程 |
| 协议核心 | 世界配对、坐标换算、帧编号、命令确认、重试、事件去重、诊断 | 两端各自的适配器 |

HTTP 保持绑定回环地址。共享内存文件使用本次实例专用目录，包含协议版本、会话标识、尺寸上限、长度与序列号。读取方只接受完整且版本一致的数据。

实现放在新的 `work/dst-mc-bridge/` 下，旧 `work/dst-mc-probe/` 保留为已验证的参照。可运行包、使用说明和验证证据集中输出到 `outputs/`。

## 5. 移动、坐标和镜头

MC 是玩家移动、跳跃和方块碰撞的计算方。停止旧原型每个 tick 把 MC 玩家传送到 DST 位置的做法。DST 对应角色保持在 MC 玩家映射的位置，供原生生物感知、追击和攻击；第一人称画面中隐藏对应角色自身。

世界配对保存一个固定原点、坐标轴变换、单位比例和地面高度，不因进程重启重新选原点。首版按 1 个 MC 方块对应 1 个 DST 世界单位开始校准，实际碰撞半径按同一比例换算。持久标识包括 DST 世界、分片、MC 存档、维度和测试区域；任一标识不符时停止旧连接并重新握手。

MC 输出每帧的视图/投影、位置、方向、FOV 和编号。DST 使用同一帧对应的镜头。图形扩展必须核验实际绘制矩阵与 MC 帧是否一致，不能只把最近一张 MC 图盖上去。尺寸、缩放和 Retina 像素比例纳入投影；匹配失败时跳过该合成帧并记录原因。

界面输入以 MC 为主；提供一个切换键把控制权交给 DST，便于操作原生菜单。切回时清理按键状态，避免持续走动或持续挖掘。断联时停止对应角色的驱动，退出融合画面。

## 6. 画面合成

先以 960×540 或等比窗口进行验证，再增加分辨率。MC 只输出需要加入 DST 的真实方块与实体；桥接用的虚拟地面、原生障碍代理和测试世界原有背景不进入合成图层。MC HUD 单独处理。

共享内存使用有尺寸上限的多缓冲帧槽。每槽包含颜色、深度、镜头、编号、时间和提交序列号。GPU 读回采用异步缓冲，发布完整帧后才允许 DST 使用配套镜头。过期、未完成、尺寸不符和会话不符的帧都不参与合成。

本地扩展优先研究 `NSOpenGLContext` 的呈现入口和 OpenGL 绘制调用，避免依赖猜测的游戏内部地址。必须识别场景与 UI 的绘制阶段，并在操作后恢复图形状态。先检查 DST 深度是否含有可用的地面和透明裁剪后的生物/树木深度；不能把 2.5D 排序值直接当作 MC 的透视深度比较。

如果原生深度不足，下一步需要针对 DST 场景绘制增加可对齐的深度通道。没有通过实际遮挡测试前，不将透明叠加或颜色混合标记为“画面融合完成”。

**第一个技术关口**：加载扩展、正确驱动第一人称镜头、取得与场景匹配的深度、合成一个真实 MC 方块，且保持 UI 正常。如果无法取得可用的绘制或镜头入口，提交失败证据并调整方案；不继续积累无法验收的建造 UI。

## 7. 建造与双向碰撞

放置、拆除、选中方块、物品栏和方块持久化沿用 MC 真实操作。MC 服务端确认成功后，发布带版本的方块变化；DST 依据确认后的状态创建或删除碰撞体。失败的放置不会留下 DST 碰撞体。

首版处理完整实心立方体；玻璃可用于验证透明表面，但仍按完整碰撞体处理。楼梯、半砖、栅栏等复杂形状暂不纳入支持清单。初始同步发送玩家附近的完整快照，后续发送增量；发现序号缺口时重新取得快照。

MC → DST：将附近方块的有效碰撞表面合并成三角网格，通过原生 `SetTriangleMesh` 创建静态碰撞；移除方块时更新网格。检查角色、生物和投射物各自的碰撞组。导航阻挡独立更新，不能以“生物走不过去”推断它会正确绕路。放置时拒绝与现有角色或生物身体重叠的块。

DST → MC：采样可行走地面边界、树木、石头、墙和其他选定障碍，把它们映射为不可见且不可挖掘的桥接碰撞形状；代理不产生方块掉落，也不成为可供普通建造替换的方块。原生物体移除后更新对应碰撞代理。

DST 生物沿原生地面移动。MC 玩家可在自建方块上跳跃和站立；首版不会自动赋予 DST 生物完整的 MC 垂直寻路。玩家处于高处时，伤害判断使用双方映射后的高度与范围，避免隔空命中。

## 8. 位置和事件连接的完善

先修复旧原型中影响新功能的接口：世界/会话隔离、固定原点、命令处理结果确认、断线重连、历史事件回放和同区块多个临时实体的加载引用计数。

命令至少包含协议版本、世界配对、会话、唯一命令编号、类型和参数；返回明确的等待、执行成功或执行失败结果。HTTP 收到命令不等于游戏线程已经执行。重试复用原编号。

伤害事件包含来源世界、事件编号、对象标识、坐标和高度、伤害类型与数值。接收方仅对匹配世界中的匹配目标处理；以事件和目标为键去重，并返回执行结果。MC 代理受到攻击后映射为 DST 原生伤害；DST 对对应角色的有效攻击映射回 MC，标记跨端来源以阻止来回转发。

爆炸事件只在真实 MC 爆炸逻辑执行后发布，同时发布实际方块变化；不能从“生成 TNT 成功”推断“爆炸成功”。取消旧模组自动生成猪人、自动发射一次 TNT 的启动行为，测试场景改为明确触发。

运行期间支持重试和幂等处理，状态变化以权威快照校正。持久事件记录与游戏存档不能形成跨进程原子事务，因此不宣称崩溃下的严格 exactly-once。重启后对未能确认的伤害先对账并报告未决状态，不能把所有旧事件重新作用到新会话。

## 9. 验收与证据

每项都区分源码编译通过、连接状态、游戏内状态和可见效果。完成定义如下：

1. **真实同屏与遮挡**：录制 MC 第一人称转动镜头、靠近方块、绕树和从方块后观察生物的过程；对应帧编号、镜头矩阵和深度有效。HUD 正常。错误遮挡不能算通过。
2. **移动与地面**：玩家步行、跳跃、撞树和接近不可通行边界；两边坐标一致，玩家不会穿过指定原生障碍。记录一段连续移动的误差与丢帧情况。
3. **建造与保存**：在 DST 地面上放置并堆叠至少 10 个真实 MC 方块，拆除其中一部分；重启同一配对世界后剩余方块位置不漂移。
4. **方块阻挡**：玩家与至少一种 DST 地面生物不能穿过方块墙；拆墙后恢复通行。检查转角、相邻区块和快速连续放拆，确认无残留碰撞体。
5. **双向事件**：MC 攻击一次 DST 测试目标，DST 生物有效攻击玩家一次，再进行一次真实 MC TNT 爆炸；两边记录能匹配，每次有效伤害只处理一次。
6. **隔离与恢复**：模拟重复请求、短时断联、进程重启和更换 DST 世界；旧世界的方块和伤害不能泄漏到新世界，连接恢复后重新核对状态。

性能先以本机连续 60 秒的 960×540 场景为样本，目标合成 30 FPS、状态同步 20 Hz。报告实际 FPS、合成延迟、内存和丢帧；目标未达到时保留功能结果，但不把性能目标标记通过。

## 10. 交付与回退

交付 Fabric 模组、DST Lua 模组、匹配当前版本的 x86_64 本地图形扩展、独立测试启动入口、卸载说明和验收证据。测试扩展通过专用启动入口加载，不替换原游戏可执行文件。加载前需要退出并重新启动 DST；执行前先确认存档已保存和本次测试的世界标识。

禁用 Lua 模组并从普通入口启动 DST，可以返回普通游戏。MC 使用独立测试副本，不写入用户原始 `DST-MC-Test` 存档。打包不包含完整游戏资源、账号信息或授权令牌。
